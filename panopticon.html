1. Concept & Overview

Core Question

Can the gaze be turned into a collective power?

The Gaze Space is an interactive web-based installation that inverts Michel Foucault's Panopticon theory. Instead of observation creating self-policing subjects, this project asks: what if the observed could weaponize the gaze that's meant to control them?

Experience Structure

One person (the Experiencer) navigates a 3D space where they're confined within a digital Panopticon alongside a representation of their "Self." Multiple Audience members watch through their screens, and their facial attention is tracked in real-time using computer vision.

As collective observation intensifies, pressure accumulates—the Panopticon structure begins to shake, the Self deforms under stress. When pressure reaches critical mass, the prison structure shatters, and the Self transforms into a luminous, free-floating form.

Design Goals

  • Create real-time networked interaction between 1 experiencer and multiple audience members
  • Use facial detection to quantify attention as measurable force
  • Visualize abstract concepts (pressure, surveillance) through 3D spatial experience
  • Build entirely web-based for accessibility—no app downloads required

System Architecture

The system consists of three main components communicating via WebSockets:

  • Experiencer Client: First-person 3D view with PointerLockControls for WASD movement
  • Node.js Server: Manages game state, tracks active gazers, calculates pressure accumulation, broadcasts updates
  • Audience Clients: Third-person 3D view with OrbitControls + face detection interface

3. Development Journey: Face Detection

The most challenging aspect was implementing reliable face detection in the browser. This required three complete attempts before finding a working solution.

Attempt 1: MediaPipe Face Mesh FAILED

The Problem

Google's MediaPipe model promised 468 facial landmarks with high accuracy. However, it relied on WebAssembly (WASM) binaries that failed to initialize. 

// Error encountered:
Uncaught TypeError: can't access property "buffer", HEAP8 is undefined

// Root cause:
- WASM module failed to initialize
- SIMD compatibility issues across browsers
- Firefox had known bugs with MediaPipe's WASM

Lessons Learned: WASM dependencies add fragility. Browser compatibility varies significantly. Black-box libraries are difficult to debug when core initialization fails.

Attempt 2: TensorFlow.js Face Landmarks PARTIAL

Pivoted to TensorFlow.js, which uses pure JavaScript/WebGL instead of WASM. Model loaded successfully, camera feed worked—but detection consistently returned 0 faces. 

const detectorConfig = {
    runtime: 'tfjs',
    maxFaces: 1,
    refineLandmarks: false,
    detectionConfidence: 0.1  // Lowered to minimum
};

const faces = await detector.estimateFaces(video);
console.log(faces.length);  // Output: 0 (always)
Debugging Process
  • Verified video dimensions were non-zero ✓
  • Added delays for metadata loading ✗
  • Lowered detection threshold to 0.1 ✗
  • Tried different camera resolutions ✗
  • Environmental requirements (lighting, angle) too strict ✗

Lessons Learned: Model complexity ≠ better results. Environmental requirements matter. Asynchronous media pipeline debugging is complex.

Attempt 3: face-api.js (vladmandic fork) SUCCESS

Finally found success with the vladmandic fork of face-api.js—a more stable, better-maintained version with simpler API. 

await faceapi.nets.tinyFaceDetector.loadFromUri(MODEL_URL);
await faceapi.nets.faceLandmark68Net.loadFromUri(MODEL_URL);

const detection = await faceapi
    .detectSingleFace(video, new faceapi.TinyFaceDetectorOptions())
    .withFaceLandmarks();

if (detection) {
    const landmarks = detection.landmarks.positions;
    const nose = landmarks[30];
    const leftEye = landmarks[36];
    const rightEye = landmarks[45];
    
    // Calculate gaze orientation
    const eyeCenterX = (leftEye.x + rightEye.x) / 2;
    const offsetX = nose.x - eyeCenterX;
    
    const normalizedX = (offsetX / eyeDistance) * 100;
    const isFacing = Math.abs(normalizedX) < 20;
}
Why This Worked?
  • TinyFaceDetector is lightweight but accurate enough
  • Better TypeScript definitions and bug fixes in vladmandic fork
  • Pixel-based coordinates easier to work with than normalized values
  • Detection latency: ~30-50ms per frame (acceptable for real-time)

4. Real-Time State Synchronization

Game State Structure

const gameState = {
    watchers: 0,              // Total connected audience members
    activeGazers: new Set(),  // Currently gazing users (by socket.id)
    totalPressure: 0,         // Accumulated pressure (0-100+)
    phase: 'waiting',         // Current phase
    gazePoints: []            // Historical data
};

Pressure Accumulation Logic

When an audience member's face is detected looking at the screen, pressure accumulates. The system went through multiple iterations to balance pacing:

Version gaze-start gaze-hold (10Hz) Result
v1 +2.0 +0.5 Too fast (~20sec)
v2 +1.0 +0.3 Still fast (~30sec)
v3 (final) +0.5 +0.15 Balanced (~50sec)
Pacing Analysis
  • 1 person gazing continuously: ~2.0 pressure/sec → 50 seconds to rupture
  • 2 people gazing: Cut time in half → 25 seconds
  • 5+ people: Dramatic acceleration → 10-15 seconds

Phase Transitions

function updatePhase() {
    const p = gameState.totalPressure;
    
    if (p < 30) gameState.phase = 'waiting';
    else if (p < 70) gameState.phase = 'critical';
    else if (p < 100) gameState.phase = 'rupture';
    // Transmutation triggered manually by experiencer
}

5. 3D Visual Effects

Morph Targets (Shape Keys)

The "Self" blob deforms based on accumulated pressure using Blender's shape keys system:

  • Base shape: Smooth organic blob
  • Deform shape: Compressed/distorted version
  • Interpolation: 0.0 (base) → 1.0 (fully deformed) based on pressure
function updateBlobMorph() {
    if (!morphTargets || morphTargets.length === 0) return;
    
    const normalizedPressure = Math.min(currentState.totalPressure / 100, 1.0);
    morphTargets[0] = normalizedPressure;
}

7. Reflection & Future Directions

What Worked

  • face-api.js proved reliable after trying 2 other libraries
  • Socket.io handled real-time sync elegantly with minimal code
  • Particle system created dramatic rupture after iteration
  • Web-based deployment made sharing easy (no install required)
  • Modular phase system made adding/modifying behaviors straightforward

What Didn't Work

  • Face detection in poor lighting remains inconsistent
  • Mobile performance lower than desired (30fps vs 60fps)
  • No persistence—state resets if server restarts
  • Single session—can't handle multiple simultaneous experiences

Critical Reflection

The Gaze Space intentionally uses the tools of surveillance—cameras, algorithms, quantified attention—to imagine their opposite. This contradiction remains unresolved. But perhaps that's the point: transformation doesn't come from perfect solutions, but from the willingness to question the structures we inhabit.

The work reveals its own limitations. You watch through screens, mediated by the very tools of digital surveillance we live under. The face detection that enables "liberation" is the same technology used for mass surveillance in authoritarian states. But perhaps this liminal space—between constraint and freedom, between complicity and resistance—is exactly where transformation begins.

Future Technical Enhancements

  • Alternative inputs: Eye tracking, heart rate, mouse intensity, audio volume
  • Session persistence: Database storage of game states and histories
  • Multi-session support: Room-based architecture for concurrent experiences
  • WebXR integration: VR mode for experiencer, AR mode for audience
  • Emotion detection: Map facial expressions to visual effects
  • Physical installation: Large-scale projection with spatial audio
